# NativeTextInput Runtime Evidence

This directory is for runtime/device evidence that cannot be replaced by
`cargo check`, static grep scripts, or unit tests.

The canonical smoke example is:

- `examples/native_text_input`
- package `makepad-example-native-text-input`
- Studio RunItem `makepad-example-native-text-input`
- diagnostic Studio RunItem `makepad-example-native-text-input-diag`
- iOS simulator Studio RunItem `makepad-example-native-text-input-ios-sim`
- Android Studio RunItem `makepad-example-native-text-input-android`
- OpenHarmony Studio RunItem `makepad-example-native-text-input-ohos`

Use `examples/text_input` and `widgets/src/text_input.rs` only as behavior
references for existing action semantics. Do not create a parallel ad hoc app
when the checked-in NativeTextInput example can cover the scenario.

## Required Files

Create the files below after running the real runtime gate. Each file must use
the exact marker lines checked by `tools/native_textinput_completion_audit.sh`.
Additional notes, screenshots paths, build ids, device ids, or logs can be
added below the marker block.
For screenshot-bearing macOS evidence, the `Screenshot:` path must point to a
readable non-empty file in the current workspace or machine where the audit is
run. For Studio-run runtime evidence, `Transcript:` must point to the saved
non-empty Studio bridge response log generated by the helper and must contain
the expected Studio responses for that gate.
Replace placeholder paths such as `/path/to/screenshot.png`; the audit rejects
placeholder marker values.

### `non-ui-static.md`

```text
Status: PASS
Verified: rustfmt example example_ui_test_compile studio_gate runtime_preflight stage_report host_queue apple android ohos schema texture cargo_check widget_tests platform_tests diff_check
AndroidTarget: checked
OhosTarget: checked
IosRelease: checked
Command: tools/native_textinput_poc_verify.sh --include-android-target --include-ohos-target
```

This file is generated by running the non-UI verifier and records the
compile/static/schema/texture evidence for P0A through P7. It does not close
runtime/device gates.

`example_ui_test_compile` means the checked-in `makepad_test` selector suite
for `examples/native_text_input` compiled with:

```bash
cargo test -p makepad-example-native-text-input --test ui --no-run
```

It only locks the smoke app's control IDs and basic test harness shape. It is
not runtime evidence: a full `makepad_test` run still starts a headless UI
server, and neither headless execution nor `--no-run` replaces the Studio
RunItem screenshots/click/type evidence below.

Runtime/device evidence files must not cite `cargo test ... --test ui` or
`makepad_test` as their command source. The completion audit rejects those
markers in runtime evidence files so the eight-stage roadmap cannot be closed
with a headless selector proxy.

Helper:

```bash
tools/native_textinput_static_evidence.sh
```

For local development environments that cannot reach crates.io or do not have
the OpenHarmony target installed, `--skip-ohos-target` can be used to regenerate
this file for debugging, but that marker will not satisfy the completion audit.
In the current sandbox, the direct OHOS target check is blocked by DNS failure
while downloading OpenHarmony NAPI crates from `static.crates.io`; recent
failures include `ohos-sys 0.2.2`, `napi-ohos 0.1.3`, and
`napi-derive-backend-ohos 0.0.7`. These target-only dependencies are pinned in
`platform/Cargo.toml` to the versions recorded in `Cargo.lock` so a networked
environment does not silently drift to newer OHOS bindings.

### `macos-composition-runtime.md`

```text
Status: PASS
RunItem: makepad-example-native-text-input
Example: examples/native_text_input
Verified: shared_host clipped scroll z_order mount_queue same_frame
BuildId: 123
AfterScreenshot: /path/to/after-screenshot.png
Transcript: docs/native-textinput-evidence/macos-composition-runtime.log
Command: tools/native_textinput_macos_composition_evidence.sh --clear-build-id N --verified "shared_host clipped scroll z_order mount_queue same_frame"
```

This closes the runtime evidence gap for P1, P1.5, and P4. It must show that
`NativeTextInput` and `NativeLabel` share the host registry, that
`clipped_native_input` stays clipped inside the scroll container without z-order
artifacts, and that `set_both_button` updates native input plus native label in
one frame through `NativeMountQueue`. `AfterScreenshot:` is captured after the
same-frame update button is clicked.

Helper:

```bash
tools/native_textinput_macos_composition_evidence.sh \
  --clear-build-id N \
  --verified "shared_host clipped scroll z_order mount_queue same_frame"
```

## Audit Command

```bash
tools/native_textinput_completion_audit.sh --stage-report
tools/native_textinput_completion_audit.sh --allow-env-deferred
tools/native_textinput_completion_audit.sh
```

`--stage-report` prints a read-only P0A/P0B/P1/P1.5/P2/P3/P4/P5/P6/P7
mapping to the evidence files currently present. It is a planning aid only; the
plain audit command remains the pass/fail gate.

`--allow-env-deferred` is for environments that cannot connect Studio,
simulators, DevEco, or devices. It passes only when the code/static gates are
complete, then prints the runtime/device checklist that still must be run in a
capable environment.

To run static/non-UI gates before checking evidence:

```bash
tools/native_textinput_completion_audit.sh --run-non-ui
```

`--run-non-ui` invokes `tools/native_textinput_static_evidence.sh` first, so it
updates `non-ui-static.md` before checking the runtime/device marker files. It
uses the final-audit defaults, including Android and OpenHarmony target checks.
For local sandbox debugging only, `--run-non-ui --skip-ohos-target` and
`--run-non-ui --skip-ios-release` forward those skips to the static evidence
helper, but the final audit still fails while `OhosTarget` or `IosRelease` is
not `checked`.

## One-Shot Completion Flow

In a clean Studio environment, after confirming the runtime bridge can connect:

```bash
tools/native_textinput_runtime_preflight.sh
tools/native_textinput_completion_run_all.sh --dry-run \
  --ios-device "iPhone 16 Simulator (UDID 00008110-001234D20E91801E)" \
  --android-device "Pixel 8 API 35 emulator (serial emulator-5554)" \
  --ohos-device "OpenHarmony RK3568 DevEco target (serial OHOS-123456)"
tools/native_textinput_completion_run_all.sh \
  --allow-no-clear \
  --ios-device "iPhone 16 Simulator (UDID 00008110-001234D20E91801E)" \
  --android-device "Pixel 8 API 35 emulator (serial emulator-5554)" \
  --ohos-device "OpenHarmony RK3568 DevEco target (serial OHOS-123456)"
```

The runner performs its own `ListBuilds` check before launching any RunItem. If
it sees an existing `makepad-example-native-text-input` build, clear that build
first or use the individual helper scripts so each `RunItem` starts from a known
fresh build.

The runner clears the first macOS smoke build before launching the composition
scenario because both use `makepad-example-native-text-input`. It then carries
forward each generated `BuildId:` as the next helper's `--clear-build-id` so the
runtime sequence stays on known fresh Studio builds.
It runs non-UI static evidence after the runtime helpers so the UI RunItem path
is not preceded by a shell `cargo check` of the same runnable target.
